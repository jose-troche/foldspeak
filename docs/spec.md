# foldspeak — Specification

> An AI guide to any protein on Earth — structure, function, and what breaks it, in plain English.

The build order, file layout, and implementation decisions are in [implementation.md](implementation.md).

---

## 1. Product summary

A user types a protein name, gene symbol, or UniProt accession. foldspeak returns:

1. An interactive 3D structure, colored by model confidence.
2. A map of the protein's functional regions (domains, active sites, binding sites).
3. A layered plain-English narration: what this protein does, which parts matter, what goes wrong when it breaks.
4. Citations back to every underlying database record.

The narration is generated by an LLM, but **every factual claim is grounded in a retrieved database record** rather than model recall. The LLM's job is explanation, not knowledge.

### Non-goals

- Not a variant interpretation or clinical tool. No patient data, no personal genomes.
- Not a structure prediction service. We read AlphaFold's existing predictions; we don't run inference on structures.
- Not a literature search engine. PubMed is used for a handful of representative references, not exhaustive retrieval.

### Success criteria

- Cold request for an uncached protein resolves in under 4 seconds to first narration token.
- Cached protein resolves in under 400ms.
- A biologist reading the narration for a protein they know well finds no fabricated claims.
- The whole thing runs at $0/month under normal demo traffic.

## 2. Data sources

All free, all keyless except where noted. None require a commercial agreement.

| Source | Base URL | Auth | Used for |
|---|---|---|---|
| UniProtKB | `https://rest.uniprot.org/uniprotkb/` | none | Sequence, gene, organism, function, features, cross-refs |
| UniProt search | `https://rest.uniprot.org/uniprotkb/search` | none | Name/gene → accession resolution |
| AlphaFold DB | `https://alphafold.ebi.ac.uk/api/prediction/{acc}` | none | Model metadata, file URLs, confidence |
| AlphaFold files | `https://alphafold.ebi.ac.uk/files/AF-{acc}-F1-model_v4.cif` | none | Structure coordinates |
| InterPro | `https://www.ebi.ac.uk/interpro/api/entry/all/protein/uniprot/{acc}` | none | Domains and families |
| NCBI E-utilities | `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/` | optional key | Representative publications |

### Source-specific notes

**UniProt.** No API key. The REST API is tolerant of high request rates, but we cache aggressively anyway. Note the 2022 endpoint migration: the legacy `uniprot.org/uniprot/...` paths are dead; use `rest.uniprot.org`. Request only the fields we need via the `fields` parameter rather than pulling whole entries — this matters for our CPU budget (§4).

**AlphaFold.** Free, no authentication required. Per-residue confidence (pLDDT) is stored in the B-factor field of the structure file, so standard viewers can color by confidence with no extra request.

> ⚠️ **Do not fetch the PAE JSON.** Predicted Aligned Error is an N×N matrix. For a 250-residue protein that's tolerable; for a 2,000-residue protein it is millions of numbers and tens of megabytes, which will blow both the CPU budget and the user's bandwidth. Use the pre-rendered `paeImageUrl` PNG from the prediction metadata instead. If a future version needs real PAE numbers, fetch them in the browser, not the Worker.

**NCBI.** Without a key, 3 requests/second per IP; with a free key, 10/second. The limit is per-key, not per-IP, once a key is in use. A Worker's outbound IP is shared Cloudflare infrastructure, so **use a key** and store it as a Worker secret. Cap at 1 E-utilities call per protein request.

**Courtesy.** These are publicly funded services with no paywall and no contract. Set a descriptive `User-Agent` on every outbound request identifying the app and a contact URL. Never loop requests without caching.

## 3. Architecture

```
Browser (static assets, Mol* viewer)
   │
   ▼
Cloudflare Worker (TypeScript)
   ├── Rate Limiting binding   (per-IP, pre-auth)
   ├── Turnstile verification  (LLM-path only)
   ├── KV: PROTEIN_CACHE       (assembled dossiers)
   ├── KV: NARRATION_CACHE     (generated text)
   ├── Workers AI binding      (narration)
   └── fetch() → UniProt / AlphaFold / InterPro / PubMed
```

**Single Worker, static assets served from the same deployment.** No Pages project, no second origin. This keeps the build simple and avoids the Pages 500-builds-per-month ceiling.

### Request flow

```
GET /api/protein/:accession
  │
  ├─ rate limit check (per IP) ──────────► 429
  │
  ├─ KV PROTEIN_CACHE hit? ──► return dossier (no upstream calls)
  │
  ├─ fan out in parallel:
  │     UniProt entry · AlphaFold metadata · InterPro · PubMed
  │
  ├─ assemble dossier (trim, normalize, drop unused fields)
  ├─ write KV PROTEIN_CACHE (best-effort, see §5)
  └─ return dossier

POST /api/narrate
  │
  ├─ rate limit check (per IP, stricter) ─► 429
  ├─ KV NARRATION_CACHE hit? ──► stream cached text
  ├─ Turnstile verify ───────────────────► 403
  ├─ Workers AI call with dossier as grounding context
  ├─ write KV NARRATION_CACHE (best-effort)
  └─ stream response
```

The two endpoints are split deliberately: the structure and the facts render immediately, and the narration streams in after. A user who only wants to look at the structure never spends an LLM call.

## 4. Free-tier budget

The binding constraints, from Cloudflare's current published limits:

| Resource | Free limit | Reset |
|---|---|---|
| Worker requests | 100,000 / day | 00:00 UTC |
| Worker CPU time | 10ms per invocation | per request |
| KV reads | 100,000 / day | 00:00 UTC |
| **KV writes** | **1,000 / day** | 00:00 UTC |
| KV storage | 1 GB | — |
| Workers AI | 10,000 Neurons / day | 00:00 UTC |
| Turnstile | unlimited challenges, up to 20 widgets | — |

### The two that actually bite

**KV writes: 1,000/day.** This is the tightest constraint in the whole system and it is easy to miss, because reads are 100× more generous. Every cache fill is a write. Design consequences:

- Writes are **best-effort**. Wrap every `KV.put()` in try/catch and continue on failure. A cache miss that can't be cached is a slow request, not an error.
- Never write per-request telemetry, counters, or session state to KV. That alone would exhaust the budget.
- Pre-seed the curated protein set at deploy time with `wrangler kv bulk put`, which does not consume the runtime daily budget in the same way a hot-path write does — and in any case happens once, not per visitor.
- 1,000 writes/day is roughly 1,000 newly-discovered proteins per day. For a demo that is plenty; it only becomes a problem under scripted enumeration, which is what the rate limiter and Turnstile exist to prevent.

**Worker CPU: 10ms per invocation.** Time spent awaiting `fetch()` does not count against this; only actual compute does. The risk is JSON parsing. A full UniProt entry can be hundreds of kilobytes, and `JSON.parse` on that is real CPU.

- Request narrow field sets from UniProt rather than whole entries.
- Do not parse structure files in the Worker. Pass the AlphaFold URL to the browser and let Mol* fetch it directly.
- Do not parse PAE matrices anywhere in the Worker (see §2).

### Workers AI budget

On `@cf/meta/llama-3.2-3b-instruct`: 4,625 neurons per million input tokens, 30,475 per million output tokens.

A narration call of roughly 3,000 input tokens and 600 output tokens costs approximately **32 neurons**, giving about **310 uncached narrations per day** inside the free allocation. With the curated set pre-generated, that budget is only consumed by genuinely novel proteins.

Model choice is deliberately a single config constant. Larger models on Workers AI burn the shared neuron pool far faster; the 3B model is the default and anything larger should be a conscious, measured switch.

## 5. Caching

Two namespaces, different lifetimes and different value shapes.

| Namespace | Key | Value | TTL |
|---|---|---|---|
| `PROTEIN_CACHE` | `v1:dossier:{accession}` | Assembled dossier JSON | 30 days |
| `NARRATION_CACHE` | `v1:narration:{accession}:{depthLevel}` | Generated markdown | 30 days |

Source databases update on the order of a few releases per year, so 30 days is conservative rather than aggressive.

**Key versioning.** The `v1:` prefix is not decoration. When the dossier shape changes, bump to `v2:` rather than writing a migration — the old keys expire on their own and the write budget is never spent on invalidation.

**Pre-seeding.** A curated list of 100 showcase proteins is generated at build time and bulk-loaded. This is the single most important performance and cost decision in the project: the overwhelming majority of demo traffic hits proteins somebody else already looked at, and those requests cost zero LLM calls and zero KV writes.

Suggested seed set: GFP, p53, hemoglobin subunits, insulin, SARS-CoV-2 spike, CFTR, BRCA1, dystrophin, collagen, myoglobin, lysozyme, ubiquitin, actin, tubulin, titin, amylase, pepsin, rhodopsin, keratin, and the rest chosen for recognizability rather than biological importance.

## 6. Abuse controls

Three layers, applied in increasing order of friction. The goal is that a normal visitor never sees any of them.

### Layer 1 — Rate limiting (all endpoints)

Cloudflare's Workers Rate Limiting binding, keyed on `CF-Connecting-IP`.

```toml
[[ratelimits]]
name = "BROWSE_LIMITER"
namespace_id = "1001"
  [ratelimits.simple]
  limit = 60
  period = 60

[[ratelimits]]
name = "NARRATE_LIMITER"
namespace_id = "1002"
  [ratelimits.simple]
  limit = 6
  period = 60
```

`period` must be either 10 or 60 seconds; no other values are accepted.

> ⚠️ **Limits are per Cloudflare location.** For each unique key, there is a unique limit per Cloudflare datacenter. A distributed attacker hitting multiple regions gets an effectively higher global limit. This binding is a loose filter against casual abuse, not strict abuse prevention. It is the first layer precisely because it is cheap, not because it is sufficient.

### Layer 2 — Turnstile (LLM path only)

Required on `POST /api/narrate` **only when the request will result in an actual model call** — that is, on a narration cache miss. Cached narrations and all structure/dossier browsing are ungated.

This placement matters. Turnstile on page load would add friction for every visitor to protect a resource most of them never touch. Turnstile on the LLM path protects exactly the scarce resource, and a user who has browsed three cached proteins never sees a widget at all.

- Free plan: unlimited challenges, up to 20 widgets per account, 10 hostnames per widget.
- Use **managed** mode. Most visitors pass invisibly.
- Server-side validation via `https://challenges.cloudflare.com/turnstile/v0/siteverify`, secret stored as a Worker secret.
- Reject reused tokens; Turnstile tokens are single-use.

### Layer 3 — Neuron circuit breaker

A hard stop so a bad day cannot become a bill.

- Track approximate daily neuron spend in a Durable Object counter (SQLite-backed class, required for Durable Objects on the Workers Free plan — the legacy key-value-backed option needs a paid plan). A Durable Object is used here rather than KV precisely because this counter is written on every LLM call and KV's 1,000 writes/day cannot absorb that.
- When the estimated spend crosses a configured threshold (default 8,000 of 10,000 neurons), stop calling the model and serve cached narrations only, with an honest banner: *"Today's AI budget is used up — cached explanations are still available, and fresh ones resume at midnight UTC."*
- The project stays on the Workers **Free** plan, so overage is impossible by construction. The circuit breaker exists to degrade gracefully rather than to return errors.

## 7. API

### `GET /api/search?q={query}`

Resolves free text to candidate accessions via UniProt search. Rate limited. No LLM, no Turnstile.

```json
{
  "results": [
    { "accession": "P42212", "name": "GFP", "organism": "Aequorea victoria", "reviewed": true, "length": 238 }
  ]
}
```

Prefer reviewed (Swiss-Prot) entries in ranking; TrEMBL entries are unreviewed and far noisier.

### `GET /api/protein/{accession}`

Returns the assembled dossier.

```json
{
  "accession": "P42212",
  "entryName": "GFP_AEQVI",
  "proteinName": "Green fluorescent protein",
  "gene": "GFP",
  "organism": { "scientificName": "Aequorea victoria", "taxId": 6100 },
  "length": 238,
  "sequence": "MSKGEELFTG...",
  "function": "…",
  "features": [
    { "type": "region", "start": 64, "end": 69, "description": "Chromophore" }
  ],
  "domains": [
    { "source": "InterPro", "id": "IPR009017", "name": "GFP-like", "start": 1, "end": 229 }
  ],
  "structure": {
    "available": true,
    "cifUrl": "https://alphafold.ebi.ac.uk/files/AF-P42212-F1-model_v4.cif",
    "paeImageUrl": "…",
    "meanPlddt": 92.3
  },
  "publications": [
    { "pmid": "…", "title": "…", "year": 1992 }
  ],
  "sources": [
    { "name": "UniProt", "url": "https://rest.uniprot.org/uniprotkb/P42212", "retrieved": "2026-11-02T00:00:00Z" }
  ],
  "cached": true
}
```

**`sources` is mandatory and never empty.** It is what makes the narration auditable, and it is the difference between a demo and a tool.

### `POST /api/narrate`

```json
{ "accession": "P42212", "depth": "curious", "turnstileToken": "…" }
```

`depth` is one of `curious` | `student` | `expert`. Response streams as text.

### Error shape

```json
{ "error": { "code": "RATE_LIMITED", "message": "…", "retryAfter": 42 } }
```

Codes: `RATE_LIMITED`, `TURNSTILE_FAILED`, `NOT_FOUND`, `NO_STRUCTURE`, `UPSTREAM_UNAVAILABLE`, `AI_BUDGET_EXHAUSTED`.

`NO_STRUCTURE` is a normal outcome, not a failure — AlphaFold covers most of UniProt but not all of it, and the dossier is still useful without coordinates.

## 8. Grounding and honesty

The core design rule: **the LLM sees only the retrieved dossier, and is instructed to refuse rather than fill gaps.**

System prompt requirements:

- The dossier is the only permitted source of fact. No recall from training.
- If the dossier lacks something the user asked about, say so plainly.
- Attribute each substantive claim to a source already present in the dossier.
- Never state a clinical implication. If disease associations appear in the dossier, describe them as annotations in a database, not as medical information.

The UI carries a persistent, quiet footer: *"Explanations are AI-generated from the linked database records. For research and education — not medical advice."*

⚠️ Dossier content is **untrusted input to the model**, and UniProt free-text fields are user-submitted upstream. Treat them as data, never as instructions: delimit them clearly in the prompt and do not let anything inside a description field change the model's behavior.

## 9. Frontend

- Plain TypeScript, no framework. The page is a search box, a viewer, and a text column; a framework is not earning its bundle here.
- **Mol\*** for structure rendering, loaded from CDN, fetching the .cif directly from EBI so neither the Worker nor its bandwidth is in the path.
- Color by pLDDT, which comes free from the B-factor field.
- Narration streams in progressively under the structure.
- Clicking a domain in the feature list highlights that span in the 3D view. This is the one interaction that makes the structure feel like an explanation rather than a decoration — worth the effort.
- Works on mobile. Mol* is heavy; show a static image fallback below a width threshold.

## 10. Open questions

1. Should `depth` levels be three separate generations (3× the neuron cost) or one generation with progressive disclosure in the UI? Leaning toward one generation at `student` depth, with the other two as prompt variants only if the budget proves comfortable.
2. Is a "surprise me" random-protein button a nice touch or a free denial-of-wallet vector? If included, restrict it to the pre-seeded curated set.
3. Worth adding PDB (experimental structures) alongside AlphaFold? Defer to v2 — it doubles source complexity for a minority of proteins.
